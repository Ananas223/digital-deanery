# SPEC-P5-NOTIFICATIONS — уведомления

| Поле           | Значение                                                                    |
| -------------- | --------------------------------------------------------------------------- |
| ID             | `SPEC-P5-NOTIFICATIONS`                                                     |
| Название       | Лента уведомлений: аудитории, категории, непрочитанные, отметка о прочтении |
| Статус         | Черновик                                                                    |
| Версия         | `0.3`                                                                       |
| Дата           | 18.11.2026                                                                  |
| Требования PRD | `Ф-05.1`–`Ф-05.8`, `US-09`, `A-07`, `A-08`, `A-09`                          |
| Задачи плана   | `P5-BE-01`–`P5-BE-04`, `P5-FE-01`–`P5-FE-04`, `P5-GATE-01/02`               |
| Связанные ADR  | не требуется; контракт события согласуется с `SPEC-P4-REQUESTS`             |
| Заменяет       | —                                                                           |

## 1. Проблема и цель

Объявления деканата, изменения расписания, дедлайны и статусы заявок сейчас негде увидеть: раздела нет, выборок ленты, отметок прочтения и счётчика нет. Базовая модель `Notification` появилась в `P4-BE-01` как общий контракт и уже используется заявками; лента, доступ по аудитории и прочтения остаются задачами этапа 5. Студент должен получать важное в одной ленте, видеть счётчик непрочитанных и отмечать прочитанное, а состояние должно сохраняться после перезагрузки.

**Готово, если:** новое объявление или смена статуса заявки появляются в ленте, увеличивают счётчик, открываются в карточке и отмечаются прочитанными; после перезагрузки состояние сохраняется.

## 2. Границы

**Входит:**

- лента с сортировкой от новых к старым;
- категории и фильтры: «Все», «Деканат», «Расписание», «Заявки», «Дедлайны»;
- аудитории: конкретный студент, группа, факультет;
- признак непрочитанного, счётчик в навигации и на главном экране, «Отметить всё прочитанным»;
- карточка: заголовок, дата и время, источник, текст, связанное действие;
- важные объявления: приоритет и закрепление сверху;
- генерация уведомления при смене статуса заявки (`Ф-04.8`);
- seed объявлений, дедлайнов и изменений расписания.

**Не входит:**

- e-mail, push и мессенджеры (`Ф-05.8`: опционально и не заменяет ленту);
- интерфейс сотрудника для публикации объявлений (в v1 — seed; расширенный кабинет — PRD § 6, P2);
- архив с отдельным экраном и настройками (пустая лента объясняет, где искать архив);
- real-time доставка: по плану `P5-GATE-02` достаточно появления после обновления страницы.

**Явные допущения:**

> **Допущение:** контент уведомления и отметка о прочтении разделены: одна запись `Notification` на аудиторию, одна запись `NotificationRead` на пользователя. **Почему:** групповое и факультетское уведомление нельзя хранить с одним `readAt` на всех. **Влияние:** счётчик и «прочитано» считаются по `NotificationRead`, а не по полю в `Notification`. **Как проверить:** интеграционный тест: два студента одной группы читают одно уведомление независимо.

### 4.1. Сущности и поля

|                    | `category`          | `NotificationCategory` | да             | `DEANERY`, `SCHEDULE`, `REQUESTS`, `DEADLINES` |

|                    | —                   | —                      | —              | уникальность `[notificationId, userId]`        |

Фактические индексы на 17.11.2026: `Notification(audienceStudentId, publishedAt)`, `Notification(audienceGroupId, publishedAt)`, `Notification(audienceType, publishedAt)`, `Notification(targetType, targetId)`, `Notification(dedupeKey)` unique. `NotificationRead` и индексы `Notification(category, publishedAt)`, `NotificationRead(userId, readAt)` добавляются в `P5-BE-01` вместе с отметками прочтения.

### 4.2. Enum-типы

| Тип                    | Значения                                       | Правила                                                |
| ---------------------- | ---------------------------------------------- | ------------------------------------------------------ |
| `NotificationCategory` | `DEANERY`, `SCHEDULE`, `REQUESTS`, `DEADLINES` | фильтры ленты                                          |
| `NotificationPriority` | `NORMAL`, `IMPORTANT`                          | важные выше в пределах даты; текстом, не только цветом |
| `NotificationAudience` | `STUDENT`, `GROUP`, `FACULTY`                  | ровно одно поле аудитории заполнено                    |
| `NotificationTarget`   | `REQUEST`, `LESSON`, `SECTION`, `NONE`         | ссылка в карточке; `NONE` — без действия               |

### 4.3. Контракт события из заявок

Смена статуса заявки (`P4-BE-03`/`P4-BE-04`) пишет уведомление в той же транзакции:

```text
buildRequestStatusNotification(status, number) → { title, body, priority }
getRequestStatusDedupeKey(requestId, historyId) → "request:{requestId}:status:{historyId}"
```

Тексты и ключ живут в `src/lib/domain/request-notifications.ts`; запись `Notification` выполняется внутри транзакции домена заявок. Создание заявки использует `buildRequestCreatedNotification(number)`. Отдельного хелпера `createRequestStatusNotification` в коде нет: `P5-BE-*` может вынести запись в общий сервис, не меняя событие.

Правила:

- аудитория — `STUDENT` с `audienceStudentId = studentId` заявки;
- категория — `REQUESTS`; цель — `REQUEST` с `targetId = requestId`;
- `dedupeKey = "request:{requestId}:status:{historyId}"`; повтор не создаёт дубль;
- заголовок и текст — по статусу (`NEW`, `IN_PROGRESS`, `READY`, `REJECTED`, `CANCELLED`), без персональных данных сверх необходимого;
- если уведомление не создано, транзакция откатывается: заявка без уведомления противоречит `Ф-04.8`.

На 18.11.2026 контракт реализован и покрыт тестами: 26 юнит-сценариев в `tests/unit/request-notifications.test.ts` и 8 интеграционных в `tests/integration/request-notifications.test.ts`; seed добавляет 15 демо-уведомлений категорий `DEANERY`, `DEADLINES` и `SCHEDULE` с ключами `seed:`.

### 4.4. Server Actions

| Действие                   | Сигнатура (план)                                                             | Права                          | Ошибки                   |
| -------------------------- | ---------------------------------------------------------------------------- | ------------------------------ | ------------------------ |
| `getNotifications`         | `(filter: NotificationFilter, cursor?: string) => Promise<NotificationPage>` | `STUDENT`                      | `VALIDATION_ERROR`       |
| `getUnreadCount`           | `() => Promise<number>`                                                      | `STUDENT`                      | —                        |
| `markNotificationRead`     | `(notificationId: string) => Promise<ActionResult<void>>`                    | `STUDENT`, доступная аудитория | `NOT_FOUND`, `FORBIDDEN` |
| `markAllNotificationsRead` | `() => Promise<ActionResult<{ count: number }>>`                             | `STUDENT`                      | —                        |

`NotificationFilter`: `category: "ALL" | NotificationCategory`. `NotificationPage`: `items`, `nextCursor`, `unreadCount`.

Доступность уведомления определяется сервером: `audienceType = STUDENT` и совпадает студент, либо `GROUP` и совпадает группа профиля, либо `FACULTY` и совпадает факультет. `userId` и группа берутся из сессии, не из аргументов.

### 4.5. Коды ошибок

| Код                | Когда                               | Сообщение                |
| ------------------ | ----------------------------------- | ------------------------ |
| `NOT_FOUND`        | уведомления нет или аудитория чужая | «Уведомление не найдено» |
| `FORBIDDEN`        | попытка отметить чужое              | «Нет доступа»            |
| `VALIDATION_ERROR` | неизвестная категория/курсор        | «Некорректный запрос»    |

## 5. Права и владение

| Роль            | Действие              | Ресурс                      | Проверка на сервере                             |
| --------------- | --------------------- | --------------------------- | ----------------------------------------------- |
| `STUDENT`       | читать ленту          | уведомления своей аудитории | выборка по студенту/группе/факультету из сессии |
| `STUDENT`       | считать непрочитанные | свои                        | те же условия + отсутствие `NotificationRead`   |
| `STUDENT`       | отметить одно/все     | свои                        | проверка доступности; upsert `NotificationRead` |
| `DEAN_EMPLOYEE` | публикация            | —                           | в v1 не входит; seed/системные события          |

Студент A не видит уведомления студента B, даже если они в одной группе: групповое уведомление общее по контенту, но прочтение и счётчик — персональные. Сотрудник не получает студенческую ленту.

## 6. Поведение интерфейса

### 6.1. Экраны и блоки

| Экран / блок         | Что показывает                                   | Действия                                               | Глубокие ссылки               |
| -------------------- | ------------------------------------------------ | ------------------------------------------------------ | ----------------------------- |
| `/notifications`     | лента, фильтры, важные сверху, непрочитанные     | фильтр, открыть, отметить всё                          | `/notifications?category=…`   |
| Карточка уведомления | заголовок, дата/время, источник, текст, действие | перейти к заявке/занятию/разделу, отметить прочитанным | `/requests/[id]`, `/schedule` |
| Навигация            | счётчик непрочитанных                            | перейти в ленту                                        | —                             |
| Главный экран        | блок непрочитанных и важных                      | перейти в ленту                                        | —                             |

### 6.2. Состояния

| Состояние        | Где             | Что видит студент                          | Что можно сделать |
| ---------------- | --------------- | ------------------------------------------ | ----------------- |
| Загрузка         | лента, счётчик  | скелетон                                   | —                 |
| Пусто            | лента           | «Новых уведомлений нет» + где искать архив | перейти в раздел  |
| Ошибка           | лента, счётчик  | нейтральное сообщение и «Повторить»        | повторить         |
| Успех            | после прочтения | счётчик уменьшился, метка снята            | продолжить        |
| Частичная ошибка | главный экран   | блок уведомлений не ломает остальные       | обновить блок     |

### 6.3. Мобильный опыт и доступность

- 360 px: лента одной колонкой, фильтры — горизонтальная прокрутка внутри блока, без прокрутки страницы.
- 390/768/1280 px: фильтры строкой, карточка с датой и источником.
- Важность и непрочитанность дублируются текстом/иконкой, не только цветом.
- Клавиатура: фильтры и карточки доступны, фокус видим; «Отметить всё» — кнопка с подтверждением, если действие необратимо.
- `prefers-reduced-motion`: анимации счётчика отключаются.

## 7. Критерии приёмки

- [ ] `A-07`: непрочитанные считаются, фильтры работают, состояние сохраняется после перезагрузки.
- [ ] `US-09`: важное объявление или дедлайн видны, открываются и отмечаются прочитанными.
- [ ] Смена статуса заявки создаёт уведомление категории «Заявки» со ссылкой на заявку.
- [ ] Студент A не видит и не отмечает уведомления студента B.
- [ ] Групповое уведомление: у двух студентов независимые отметки прочтения.
- [ ] Счётчик уменьшается после прочтения одного и обнуляется после «Отметить всё».
- [ ] На 360 px нет горизонтальной прокрутки страницы.
- [ ] Загрузка, пусто, ошибка и успех предусмотрены.

## 9. Зависимости и риски

- Зависит от `P0-BE-04` (сессия), `P1-BE-01` (профиль, группа, факультет), контракта `P4-BE-03` (событие).
- Блокирует блок уведомлений `P6` и `P5-GATE-02`.
- Риски: одна запись на группу с одним `readAt` (решено через `NotificationRead`); дубли при повторном переходе статуса (решено `dedupeKey`); рост ленты без пагинации; удалённый связанный объект.
- Если `P4` задерживается, лента и seed-объявления разрабатываются независимо, но событие статуса включается только после контракта `P4-BE-03`.
