## 1. Проблема и цель

В v4 главная подключает `getDashboardData`: учебную сводку, ближайший экзамен, активные заявки и непрочитанные уведомления; занятия дня и быстрые действия доступны. Серверные контракты сохранены; реализация интерфейса не означает закрытия критериев приёмки.

**Готово, если:** после входа студент за минуту видит ближайшее занятие, состояние учёбы, активные заявки и непрочитанные уведомления; каждый блок ведёт в работающий раздел и не ломает экран при пустых данных.

## 2. Границы

**Входит:** агрегированный серверный запрос, блоки главного экрана, глубокие ссылки, состояния, адаптивность, тесты агрегата.

**Не входит:** новые доменные правила; изменение контрактов расписания, успеваемости, заявок и уведомлений; редактирование данных с главного экрана; общий кеш персонализированных данных.

## 3. Контракт данных

```text
getDashboardData(userId: string, now?: Date): Promise<DashboardData>
```

| Поле                  | Тип                                            | Источник                                | Пустое значение                               |
| --------------------- | ---------------------------------------------- | --------------------------------------- | --------------------------------------------- |
| `student`             | `{ firstName, groupCode } \| null`             | профиль                                 | профиль отсутствует → нейтральное приветствие |
| `nearestLesson`       | `LessonCard \| null`                           | `getTodaySchedule`                      | `null` → «На сегодня занятий нет»             |
| `gradesSummary`       | `GradesSummary \| null`                        | `getSemesterOverview` текущего семестра | `null`/`NO_DATA` → объяснение                 |
| `nearestExam`         | `SessionExam \| null`                          | сессия текущего семестра                | `null` → «Ближайших экзаменов нет»            |
| `activeRequests`      | `RequestSummary[]`                             | заявки в `NEW`/`IN_PROGRESS`            | `[]` → «Активных заявок нет»                  |
| `unreadNotifications` | `{ count: number; items: NotificationItem[] }` | лента `P5`                              | `0` → «Непрочитанных нет»                     |
| `unavailable`         | `DashboardBlockKey[]`                          | результат сборки блоков                 | `[]` → все блоки загружены                    |

`DashboardBlockKey` — `student`, `nearestLesson`, `gradesSummary`, `nearestExam`, `activeRequests`, `unreadNotifications`. Ключи добавляются в `unavailable` в этом фиксированном порядке; сбой загрузки успеваемости помечает и `gradesSummary`, и `nearestExam`, потому что оба берутся из `getSemesterOverview`.

Правила:

- `userId` — только из проверенной сессии; клиентский ID игнорируется. `now` — необязательный параметр для детерминированных тестов.
- Запрос только для текущего студента, без общего кеша и `unstable_cache`; динамический рендер.
- Блоки независимы: сбой одного не должен ронять остальные (`Promise.allSettled`). Агрегат возвращает частичный результат с пометкой в `unavailable`, а не общую ошибку. Отсутствие профиля или данных — корректный пустой результат, а не сбой.
- «Активные заявки» — `NEW` и `IN_PROGRESS`; `READY`/`REJECTED`/`CANCELLED` в блок не входят; не более 3 новых сверху.
- «Ближайшая пара» — текущая, затем следующая по фактическому времени; при переносе используется эффективное состояние; отменённые занятия не участвуют.
- «Ближайший экзамен» — текущий (уже начавшийся), затем следующий; прошедшие не показываются.
- `unreadNotifications.items` — не более 3 важных/новых; `count` — полное число непрочитанных; полный список — в ленте.

### 3.1. Утренний бриф (`Ф-00.8`, `US-16`, `A-17`)

```text
getMorningBrief(userId: string, now?: Date): Promise<MorningBriefData>
```

| Поле          | Тип                              | Источник                                      | Пустое значение                         |
| ------------- | -------------------------------- | --------------------------------------------- | --------------------------------------- |
| `now`         | `MorningBriefLesson \| null`     | `getTodaySchedule` + `pickNearestLesson`      | `null` → карточка не показывается       |
| `changes`     | `MorningBriefChange[]`           | уведомления `SCHEDULE`/`REQUESTS`, 7 дней     | `[]` → карточка не показывается         |
| `action`      | `MorningBriefAction \| null`     | заявки, успеваемость, сессия                  | `null` → карточка не показывается       |
| `unavailable` | `MorningBriefBlockKey[]`         | результат сборки блоков                       | `[]` → все блоки загружены              |

`MorningBriefBlockKey` — `now`, `changes`, `action`; ключи добавляются в фиксированном порядке. Если недоступны заявки или успеваемость, `action` помечается недоступным целиком.

Правила:

- `userId` — только из проверенной сессии; `now` — для детерминированных тестов. Только данные текущего студента, без общего кеша и `unstable_cache`.
- Блоки независимы (`Promise.allSettled`): сбой одного не роняет остальные; страница показывает частичный результат.
- «Сейчас» — текущее занятие, иначе ближайшее следующее; отменённые не участвуют, перенос показывается как изменение. Если занятия нет, карточка не выводится.
- «Изменилось» — только уведомления категорий `SCHEDULE` и `REQUESTS` за последние 7 дней, сортировка по `publishedAt` по убыванию, не более 2. Ссылка ведёт на заявку, занятие или ленту уведомлений. Новые события не выдумываются.
- «Требует действия» — ровно одно, фиксированный приоритет: просроченная открытая заявка (`dueAt < now`, самая ранняя) → готовая заявка → заявка со сроком ≤ 3 дней (самая ранняя) → задолженность → экзамен ≤ 7 дней → `null`.
- Новых оценок в «Изменилось» нет: отдельного события оценки в ленте не существует. LLM не используется; бриф полностью детерминирован.
- Если все блоки пусты, показывается «Пока всё спокойно»; ошибка блока объясняется отдельно и не скрывает остальные.

## 4. Поведение интерфейса

### 4.1. Блоки

| Блок             | Что показывает                                                        | Действие / ссылка                                 |
| ---------------- | --------------------------------------------------------------------- | ------------------------------------------------- |
| Приветствие      | имя, текущая дата по Москве                                           | —                                                 |
| Утренний бриф    | до 3 карточек: «Сейчас», «Изменилось», «Требует действия»             | карточка занятия, заявка, уведомление, раздел     |
| Ближайшая пара   | дисциплина, время, аудитория, преподаватель, метка «сейчас»/изменение | `/schedule` или карточка занятия                  |
| Сводка учёбы     | средний балл, задолженности, ближайший экзамен                        | `/grades`, проблемная дисциплина                  |
| Активные заявки  | тип, номер, статус; до 3                                              | `/requests`, карточка заявки                      |
| Уведомления      | непрочитанные и важные; до 3                                          | `/notifications`, карточка уведомления            |
| Быстрые действия | «Заказать справку», «Расписание на неделю», «Все оценки»              | `/requests/new`, `/schedule?view=week`, `/grades` |

### 4.2. Состояния

| Состояние        | Где            | Что видит студент                                   | Что можно сделать         |
| ---------------- | -------------- | --------------------------------------------------- | ------------------------- |
| Загрузка         | каждый блок    | скелетон блока, не пустая страница                  | —                         |
| Пусто            | блок           | объяснение, почему данных нет, и следующее действие | перейти в раздел          |
| Ошибка блока     | один блок      | нейтральное сообщение и «Повторить»                 | повторить блок            |
| Частичная ошибка | страница       | остальные блоки работают                            | обновить недоступный блок |
| Пусто (бриф)     | утренний бриф  | «Пока всё спокойно», если все три блока пусты       | перейти в разделы         |
| Ошибка брифа     | карточка       | ошибка только этого блока, остальные видны          | обновить страницу         |
| Успех            | после действия | обновлённые данные без мигания пустого экрана       | —                         |

### 4.3. Мобильный опыт и доступность

- 360 px: блоки одной колонкой, быстрые действия не перекрывают навигацию, нет горизонтальной прокрутки.
- 390/768/1280 px: сетка блоков; приоритет — ближайшая пара и сводка.
- Каждый блок — ссылка/кнопка с понятным доступным именем; статусы дублируются текстом.
- Клавиатура: порядок фокуса соответствует визуальному; фокус видим.
- `prefers-reduced-motion`: анимации появления блоков отключаются.

## 5. Критерии приёмки

- [ ] `Ф-00`: после входа видны приветствие, ближайшее занятие, сводка, активные заявки, непрочитанные уведомления и быстрые действия.
- [ ] `US-01`: студент понимает структуру кабинета без инструкции.
- [ ] `US-02`: ближайшее занятие и изменение видны с главного экрана.
- [ ] `US-06`: после создания заявка появляется в блоке активных.
- [ ] `US-09`: счётчик непрочитанных виден и ведёт в ленту.
- [ ] `A-08`: на 360 px нет горизонтальной прокрутки.
- [ ] `A-09`: загрузка, пусто, ошибка и частичная ошибка предусмотрены.
- [ ] `A-12`: нет неработающих кнопок и пустых блоков без объяснения.
- [ ] `Ф-00.8`/`A-17`: утренний бриф показывает не более трёх карточек, только данные текущего студента; пустое состояние и ошибка объяснены.
- [ ] `US-16`: студент понимает, что сейчас, что изменилось и что требует действия, и переходит по ссылкам.
- [x] Агрегат не раскрывает данные другого студента; при пустых данных работает (`P6-BE-02`).

## 7. Зависимости и риски

- Зависит от контрактов `T1`–`T4`: расписание (`P2`), успеваемость (`P3`), заявки (`P4`), уведомления (`P5`).
- Каркас блоков можно собрать после `P0-FE-01`; агрегат включается по мере готовности источников, каждый блок отдельно.
- Блокирует `P6-GATE-01/02`, `P7-GATE-02`.
- Риски: последовательные запросы дают медленный LCP; общий `Promise.all` роняет весь экран при сбое одного блока; дублирование форматирования; кеширование персонализированных данных.
- Если источник не готов, блок показывает честное пустое состояние, а не фиктивные данные.
