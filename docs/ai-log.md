## Как вести

- Пополнять по ходу каждого этапа, а не в конце: запись добавляется при завершении задачи или при существенной ошибке/исправлении.
- Для каждого этапа фиксировать: инструмент (и модель, если применимо), задачу, суть ключевого промпта, результат, ошибки и исправления.
- Промпты приводить кратко — только главные, в виде сути. Секреты и персональные данные в журнал не попадают.
- Новые сторонние материалы, появившиеся благодаря ИИ, фиксируются также в `docs/third-party.md`.

- `README.md` переписан: запуск, переменные окружения, демо-аккаунты, команды, тесты, структура и ограничения.

**Проверки.**

- `prisma validate` — схема валидна; `prisma generate` — Prisma Client 7.10.1.
- `eslint .` — 0 ошибок и предупреждений; `tsc --noEmit` — 0 ошибок.
- `npm run test` — 6 файлов, 39 тестов пройдено.
- `npm run test:e2e` — 37 тестов пройдено (2 входа в `setup` + 35 сценариев).
- `npm run build` — production-сборка и проверка типов пройдены.
- Сканирование `.next/static` на `BETTER_AUTH_SECRET`, `DATABASE_URL`, демо-пароль и `postgresql://` — 0 совпадений.
- `npm run gate` — типы, линтер, Vitest, Playwright и сборка пройдены.

**Ошибки и исправления.**

- Playwright загружал конфигурацию как CommonJS, `import.meta.url` падал. Заменено на `process.cwd()`.
- Спецификации импортировали `test` из `@playwright/test`, поэтому кастомные фикстуры считались неизвестными параметрами. Импорт переведён на `./fixtures`.
- Поле пароля не находилось по точной подписи: обязательный `*` входит в доступное имя. Добавлены помощники `getByRole("textbox", { name: /^Пароль/ })` и `/^E-mail/`.
- `getByRole("alert")` совпадал с route announcer Next.js. Проверка сужена фильтром по тексту ошибки.
- ESLint принимал колбэк `use` в фикстурах за React-хук. Добавлено локальное отключение правила для `tests/e2e`.
- Пользовательские контексты не наследовали viewport теста. `baseURL` и `viewport` передаются в `browser.newContext`.

## Ограничения журнала

- В журнал не попадают секреты, токены, cookie, пароли, реальные персональные данные и содержимое `.env`.
- Промпты приведены в виде сути; полные тексты остаются в истории сессий и не публикуются.
- Журнал описывает процесс, а не заменяет план: статусы задач ведутся только в `docs/DEVELOPMENT_PLAN.md`.
