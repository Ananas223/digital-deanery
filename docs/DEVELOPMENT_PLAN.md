**Крупные этапы.**

`0. Фундамент → 1. Вход и профиль → 2. Расписание → 3. Успеваемость → 4. Заявки → 5. Уведомления → 6. Главный экран → 7. Качество и приёмка → 8. Размещение и сдача`

Крупные этапы и их гейты остаются контрольными точками. Они **не являются строгой очередью**: после этапа 0 и фиксации контрактов этапы 2, 3 и 4 можно вести одновременно; уведомления (этап 5) стартуют, как только готов контракт событий заявок, не дожидаясь всего этапа 4.

**Параллельные потоки.**

| `T4. Уведомления` | `P5-*` | После `P0-BE-04` и контракта событий `P4-BE-02`/`P4-BE-03` | `P6`, `P7` |
| `T5. Главный экран` | `P6-*` | Каркас — после `P0-FE-01`/`P0-FE-02`; агрегат — после контрактов `T1`–`T4` | `P7` |
| `T6. ИИ-помощник` | `P9-AI-*` | После `P1-BE-01` и read-контрактов `T1`–`T3` | Не блокирует ядро |
| `T7. Качество и сдача` | `P7-*`, `P8-*` | Проверки — постоянно; финальный гейт — после `T0`–`T5`; `P8-DE-01` — после этапа 0 | Сдачу |

**Правила параллельной работы.**

1. Контракт важнее порядка: задача фронтенда начинается после фиксации Zod-схем и сигнатур действий, а не после завершения всего бэкенда этапа.
2. Один агент — один поток или одна задача. Два агента не правят одни и те же файлы одновременно; общий файл (`schema.prisma`, навигация, дизайн-токены) меняется отдельной задачей или по согласованию.
3. Ветки — по потокам (`feat/t1-schedule`, `feat/t2-grades`, `feat/t3-requests`). Интеграция в `main` — небольшими коммитами после локальных проверок.
4. Гейт этапа закрывается, когда готовы все его задачи и проверки. Независимый поток не ждёт закрытия чужого гейта, если его собственные зависимости выполнены.
5. Общие контракты и `schema.prisma` фиксируются заранее; миграции разных потоков не смешиваются в одной задаче.
6. Если параллельные задачи конфликтуют по смыслу или файлам — остановиться, зафиксировать блокер в плане и согласовать порядок.

**Сквозное требование ко всем этапам.** По завершении каждой задачи этапа заполняется запись в `docs/ai-log.md`: инструмент, задача, ключевой промпт, результат, ошибки и исправления. Это часть Definition of Done задачи, а не отдельная работа в конце.

**Вне плана ядра.** Дополнительные функции из PRD § 6, кроме ИИ-помощника: он вынесен в отдельный опциональный поток `T6`. Кабинет сотрудника отмечен отдельно как опциональный. Размещение и сдача — этап 8.
