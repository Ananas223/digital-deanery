# ADR 0005. ИИ-помощник: read-only инструменты, провайдер и эфемерная история

| Поле                | Значение                                                                                                                                   |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Статус              | Принято; бэкенд реализован 19.11.2026                                                                                                      |
| Дата                | 18.11.2026 (реализация — 19.11.2026)                                                                                                       |
| Контекст            | Этап 9, задачи `P9-AI-00`–`P9-AI-07`; требования `Ф-06`, `US-12`, `A-13` в `docs/PRD.md`                                                   |
| Связанные документы | [`docs/specs/p9-ai-assistant.md`](../specs/p9-ai-assistant.md), `docs/PRD.md`, `docs/DEVELOPMENT_PLAN.md`, `AGENTS.md` § 2.1, § 3.6, § 3.7 |

## Контекст

Помощник отвечает студенту на вопросы о его расписании, успеваемости, заявках и уведомлениях. По `AGENTS.md` § 3.7 инструменты по умолчанию только читают данные, `userId` берётся из проверенной сессии, список инструментов фиксирован, ключ провайдера хранится только на сервере, а логи не содержат промптов с персональными данными. Продуктовое поведение закреплено в `Ф-06`: помощник не изменяет данные и не хранит историю на сервере.

Одновременно действует ограничение § 3.6: мажорная версия Vercel AI SDK и подключение нового внешнего сервиса требуют ADR с проверкой совместимости. Нужно выбрать версию SDK, способ подключения провайдера и модель хранения истории так, чтобы замена провайдера не затрагивала фронтенд и ядро.

## Рассмотренные варианты

| Вариант                                                      | Плюсы                                                                      | Минусы                                                                                                 |
| ------------------------------------------------------------ | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| Помощник с инструментами записи (создание и отмена заявок)   | Выглядит эффектнее, сокращает путь до заявки                               | Требует подтверждения, идемпотентности и новых тестов; дублирует `Ф-04`; риск случайной мутации данных |
| Read-only помощник с инструментами поверх доменных читателей | Минимум кода, нет новых таблиц, соответствует § 3.7, ядро не затрагивается | Не выполняет действия; ценность ограничена объяснением и навигацией                                    |
| Без LLM: FAQ и поиск по разделам                             | Полностью детерминирован, нет внешней зависимости                          | Не отвечает на вопрос в свободной форме; не даёт эффекта «помощник»                                    |

Провайдер:

| Вариант                                    | Плюсы                                             | Минусы                                                         |
| ------------------------------------------ | ------------------------------------------------- | -------------------------------------------------------------- |
| OpenRouter + DeepSeek                      | Быстрый старт, знакомый API, низкая цена за токен | Внешний сервис и баланс; доступность и оплата требуют проверки |
| Российский провайдер (GigaChat, YandexGPT) | Оплата и доступность из России проще              | Другой формат API, нужен отдельный адаптер                     |
| Локальная модель                           | Нет внешней зависимости                           | Тяжёлый рантайм, не влезает в бюджет времени и хостинга        |

## Принятое решение

1. **Объём — только чтение.** Четыре инструмента (`getSchedule`, `getGrades`, `getRequests`, `getNotifications`) — тонкие обёртки над существующими доменными читателями. Прямой Prisma в инструментах запрещена. Создание заявки через помощника вынесено в `P9-AI-07` и в текущий объём не входит.
2. **SDK — Vercel AI SDK 6.x, точные версии `ai@6.0.333` и `@openrouter/ai-sdk-provider@2.10.0`.** Обе зафиксированы без диапазона: `latest` у SDK — 7.x, у адаптера — 3.x, они требуют `ai@7` и несовместимы с этим решением. Мажорное обновление — только новым ADR с полным прогоном тестов.
3. **Провайдер — за адаптером и переменными окружения.** `AI_PROVIDER_API_KEY`, `AI_MODEL`, `AI_ASSISTANT_ENABLED` задают подключение; фронтенд работает с UI-message stream и от провайдера не зависит. Стартовый вариант — OpenRouter + DeepSeek, `AI_MODEL` по умолчанию `deepseek/deepseek-v4.1-flash`; замена на российского провайдера не меняет контракт `POST /api/ai/chat`.
4. **История — эфемерная.** Сообщения живут в состоянии клиента и уходят на сервер в каждом запросе. Сервер не сохраняет промпты и ответы, `schema.prisma` и миграции не меняются.
5. **Флаг и деградация.** `AI_ASSISTANT_ENABLED=false` отключает маршрут и панель; маршрут отвечает `503 AI_UNAVAILABLE` без обращения к провайдеру. Ядро работает независимо.
6. **Ограничения.** Проверка сессии до чтения тела, лимит запросов на пользователя, суточный лимит, `maxOutputTokens` и ограничение числа шагов инструментов; ключ только в окружении и никогда в клиентском бандле.

### Реализация 19.11.2026

| Решение       | Факт                                                                                                                                 |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| SDK и адаптер | `ai@6.0.333`, `@openrouter/ai-sdk-provider@2.10.0`, `@ai-sdk/provider@3.0.19` (dev, только для типов тестов)                         |
| Инструменты   | `src/lib/ai/tools.ts`, схемы и мапперы — `src/lib/ai/tool-schemas.ts`; ошибка читателя превращается в нейтральный `available: false` |
| Маршрут       | `createAiChatHandler(deps)` в `src/lib/ai/chat-handler.ts`, тонкий `POST` в `src/app/api/ai/chat/route.ts`                           |
| Лимиты        | 20 запросов / 10 минут и 100 / 24 часа, в памяти процесса; без таблиц и миграций                                                     |
| Бюджет        | `maxOutputTokens = 800` на шаг, `stepCountIs(4)`; фактический расход и имена инструментов пишутся в лог                              |
| Ошибки        | до старта стрима — настоящий `503`/`500`; после старта — `200` и нейтральная часть `error` в UI-message stream                       |
| Наблюдаемость | `requestId`, шаг, `finishReason`, токены, имена инструментов, длительность, имя ошибки; промпты и ПДн не пишутся                     |

Процессный лимитер — сознательное ограничение демо: при нескольких экземплярах приложения счётчики не разделяются. Переход на общий store потребует отдельного ADR (таблица или Redis), потому что текущая спецификация запрещает менять схему БД.

## Последствия

- Контракт для фронтенда стабилен: смена провайдера или модели не требует изменений панели.
- Нет новых таблиц, миграций и персональных данных в БД; история исчезает после перезагрузки по `Ф-06.6`.
- Появляется внешняя зависимость: при недоступности провайдера помощник отключается, но кабинет сохраняет работоспособность (`P9-AI-GATE-02`).
- Качество ответа ограничено данными инструментов: модель не получает произвольный доступ к БД и не может выйти за закрытый список.
- Требуется контроль бюджета токенов и логов без промптов; ключ подлежит ротации при подозрении на утечку.
- Сценарий записи остаётся в парковке и при возврате потребует отдельного ADR и подтверждения владельца продукта.
