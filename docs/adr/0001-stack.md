# ADR 0001. Стек прототипа «Цифровой деканат будущего»

| Поле     | Значение                                                                                                                                                       |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Статус   | Принято                                                                                                                                                        |
| Дата     | 14.11.2026                                                                                                                                                     |
| Контекст | Конкурсный прототип личного кабинета студента; ограниченное время; один репозиторий; требования к безопасности и мобильному опыту — `docs/PRD.md`, `AGENTS.md` |
| Заменяет | Предыдущую фиксацию стека от 11.11.2026 (Next.js, Tailwind CSS, shadcn/ui, PostgreSQL, Prisma, Better Auth)                                                    |

## Контекст

Прототип должен за короткое время показать полноценный кабинет студента: вход, профиль, расписание, успеваемость, заявки, уведомления и главный экран. Требования конкурса запрещают реальные персональные данные, требуют работы на экране 360 px, серверной проверки прав и отсутствия секретов в клиенте. Дополнительно нужен ИИ-помощник по кабинету, но он не должен блокировать ядро.

Ограничения:

- один разработчик и ИИ-агенты, поэтому важны единый язык, типизация и минимум инфраструктуры;
- серверная логика и доступ к данным не могут жить в браузере;
- стек должен быть лицензионно совместим и поддерживаться;
- размещение и инфраструктура в этом решении не рассматриваются.

## Решение

### Frontend

| Технология                   | Роль                                                                     |
| ---------------------------- | ------------------------------------------------------------------------ |
| Next.js (App Router)         | Маршрутизация, Server Components, единый проект для UI и сервера         |
| React                        | Компонентная модель                                                      |
| TypeScript (strict)          | Типы на клиенте и сервере, раннее обнаружение ошибок контрактов          |
| Tailwind CSS v4              | Единственная система стилей, CSS-first токены                            |
| shadcn/ui                    | Паттерны компонентов и доступная разметка на общих токенах               |
| Base UI                      | Примитивы доступности без навязанного визуального стиля                  |
| Motion                       | Осмысленные переходы и обратная связь, с учётом `prefers-reduced-motion` |
| Recharts                     | Графики успеваемости и сводок с текстовой альтернативой                  |
| React Hook Form              | Состояние форм и ошибки                                                  |
| Zod                          | Схемы валидации, общие для формы и сервера                               |
| Lucide React                 | Единый набор иконок                                                      |
| React Context + `useReducer` | Локальное UI-состояние: фильтры, диалоги, панели                         |

### Backend

| Технология             | Роль                                                 |
| ---------------------- | ---------------------------------------------------- |
| Next.js Server Actions | Изменения данных из форм и интерфейса                |
| Next.js Route Handlers | API-маршруты, стриминг и служебные эндпоинты         |
| PostgreSQL             | Единое хранилище учебных данных                      |
| Prisma ORM             | Схема, миграции, типизированные запросы и seed       |
| Better Auth            | Вход по паролю, серверные сессии, выход              |
| RBAC                   | Роли и матрица «роль → действие → ресурс» на сервере |
| Zod                    | Повторная серверная валидация входных данных         |

### AI (опциональный трек)

| Технология       | Роль                                                |
| ---------------- | --------------------------------------------------- |
| Vercel AI SDK    | Вызов модели и стриминг ответа на сервере           |
| Agent Tools      | Ограниченный набор инструментов с Zod-схемами входа |
| LLM Provider API | Внешняя модель; ключ только в переменных окружения  |

### Тесты

| Технология | Роль                                                            |
| ---------- | --------------------------------------------------------------- |
| Vitest     | Юнит- и интеграционные проверки прав, схем, статусов и расчётов |
| Playwright | E2E-сценарии на десктопе и на 360 px                            |

## Обоснование выбора

- **Один проект Next.js вместо отдельного backend.** Server Actions и Route Handlers закрывают серверные задачи без второго приложения, второго деплоя и дублирования типов. Для конкурсного прототипа это снижает стоимость поддержки.
- **TypeScript strict + Zod.** Контракт между формой и сервером описывается один раз и проверяется на обеих сторонах; ошибки типов и данных обнаруживаются до демонстрации.
- **Tailwind CSS v4 + shadcn/ui + Base UI.** Быстрая адаптивная вёрстка и доступные примитивы без собственной библиотеки компонентов. shadcn/ui даёт паттерны, Base UI — поведение и доступность, визуальный стиль остаётся собственным.
- **Recharts и Motion — точечно.** Графики и анимации добавляются только там, где помогают понять данные или переход, и не превращаются в тяжёлую зависимость для всех экранов.
- **React Context + `useReducer` вместо глобального state-менеджера.** Локального состояния немного; серверные данные остаются в Server Components и Server Actions. Дополнительная библиотека не окупается.
- **PostgreSQL + Prisma ORM + Better Auth.** Реляционная модель естественно описывает студентов, группы, занятия, оценки, заявки и уведомления. Prisma даёт миграции и типы, Better Auth — проверенные сессии и хеширование паролей вместо самописной аутентификации.
- **RBAC на сервере.** Роль и владелец ресурса проверяются рядом с данными; интерфейс лишь подсказывает доступные действия.
- **Vercel AI SDK + Agent Tools.** Помощник получает только явно описанные read-only инструменты, а изменения выполняются обычными Server Actions после подтверждения. Трек можно отключить без потери ядра.

## Совместимость и версии

- **Prisma ORM 7.x.** Better Auth пока не подтвердил совместимость со следующей мажорной версией Prisma. Пока совместимость не проверена, остаёмся на 7.x; обновление — только через новый ADR и полный прогон тестов.
- **Tailwind CSS v4.** Токены описываются в CSS, конфигурация не дублируется в JavaScript.
- **Base UI и shadcn/ui.** Не смешивать два набора примитивов в одном компоненте: shadcn/ui используется как слой паттернов поверх Base UI.
- Версии фиксируются lock-файлом. Мажорные обновления Next.js, React, Prisma, Better Auth, Base UI и Vercel AI SDK — только через ADR.

## Последствия

Положительные:

- единый типизированный проект и один способ локального запуска;
- серверная авторизация и валидация по умолчанию;
- быстрый старт UI и понятные правила для ИИ-агентов;
- ИИ-помощник изолирован и не блокирует ядро.

Отрицательные и риски:

- Next.js и Vercel AI SDK быстро меняются; нужна фиксация версий и проверка совместимости;
- Server Actions требуют дисциплины: каждое действие обязано само проверять сессию, роль и владельца ресурса;
- Recharts и Motion увеличивают клиентский бандл — подключать только к нужным маршрутам и проверять бюджет;
- при недоступности LLM-провайдера помощник должен деградировать, а не ломать кабинет.

## Отклонённые варианты

- **Отдельный backend (NestJS/Express) и SPA.** Больше кода, второй деплой и дублирование контрактов; для прототипа избыточно.
- **Глобальный state-менеджер (Redux/Zustand).** Серверные данные уже приходят из Server Components; отдельный store создал бы второй источник истины.
- **Собственная аутентификация и сессии.** Риск ошибок в хешировании, cookie и CSRF; Better Auth закрывает это проверенной реализацией.
- **Прямой вызов LLM из браузера.** Раскрывает ключ и обходит серверные проверки прав; запрещено.
- **Другая UI-библиотека вместо shadcn/ui + Base UI.** Смешение стилей и потеря контроля над доступностью; текущий набор достаточен.
